智能运维故障分析助手 主推项目

大模型应用开发 · 2026.03 – 2026.06 · 独立开发

Dify + FastAPI + RAG + Redis

基于 Dify 与 FastAPI 构建的 Linux 服务器故障自动诊断助手。把「翻文档、看监控、问同事」这三件分散的事， 串成一条可复现的推理流水线：自动采集真实指标 → 检索知识库 → 定位根因 → 输出分级处置命令， 并把每次处置结果沉淀进历史库，下次同类问题直接复用。

STEP 01意图理解自然语言 → 结构化工单（故障类型 / 主机 / 时间窗 / 紧急度）
STEP 02知识检索向量 + BM25 双路召回，RRF 融合重排，命中手册与历史案例
STEP 03指标分析Function Calling 触发 18 项 Shell 采集，按 USE 方法逐项体检
STEP 04方案生成输出根因 + 置信度 + 证据链 + 只读/危险分级命令
  • Agent 流程设计：在 Dify 上搭建四阶段推理链，支持多轮对话式追问，链路可视化、Prompt 可热更新。
  • 工具调用：封装 18 项服务器指标采集接口（CPU / 内存 / 磁盘 / 网络 / 系统），并发执行 + 超时熔断，单项失败不影响整体。
  • 知识库构建：导入 Linux 命令手册与常见故障案例，采用「向量检索 + 关键词匹配」混合召回，解决短 query 语义漂移。
  • 后端服务：FastAPI 提供 RESTful 接口与异步调用逻辑，支持多模型接入与高并发查询；Redis 缓存指标与历史故障。
  • 工程细节：Redis / Embedding / 采集脚本三重降级，断网或非 Linux 环境也能跑通；18 项脚本纯 Shell 零依赖，可单独使用。

基于机器学习的图书推荐系统 后端 + 算法

后端与推荐算法开发 · 2025.11 – 2026.03

Flask + MySQL + Redis + TF-IDF / Item-CF

针对图书信息过载与推荐冷启动问题，采用 B/S 架构前后端分离，划分用户管理、图书管理、行为采集、 推荐计算与后台管理五大模块，并用离线评估 + 并发压测验证效果。

  • 内容推荐：基于图书标签与摘要构建 TF-IDF 特征向量，用余弦相似度计算相似图书，缓解新书冷启动。
  • 协同过滤：基于用户-图书行为矩阵实现 Item-CF，并融合权威评分生成 Top-N 推荐结果。
  • 工程实现：Flask + MySQL + Redis 完成后端接口与数据缓存；JMeter 完成并发压测。
  • 效果验证：基于 Book-Crossing 子集做离线评估，Precision / Recall / F1 均有提升。
